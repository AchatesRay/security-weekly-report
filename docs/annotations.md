# 选文标注（人工反馈 → 规则调优）

> 一句话：阅读报告时顺手点两下，把"这条该不该收"沉淀成证据；系统**不会**因此改动
> 当天报告，只在下次调词表/权重/信源等级时拿来当依据。

## 1 定位与边界

| 是 | 不是 |
|---|---|
| 规则调优的样本来源（词表、权重、信源等级、配额） | 即时干预：标注**不会**把条目撤下或置顶 |
| 可复盘的判据（带当时内容快照与评分拆解） | 训练数据 / 模型微调（一期不涉及） |
| 只对登录用户可见的旁路功能 | 公开页面上的读者互动（读者完全看不到入口） |

三条设计红线：

1. 标注不参与 10 步管道，任何时候都不影响当天的报告与收录结果。
2. 标注数据必须放 `data/state/annotations/`（`data/` 根目录会在每次开跑被清空）。
3. 标注随行保存内容快照（标题、信源、分类、评分拆解、命中词）——报告数据 14 天清理、
   滚动库 14 天滑出，只存 `item_id` 事后无法复盘。

## 2 怎么用

1. 直接打开报告页即可（全站已在登录之后，**无需任何 URL 参数**）：

   ```
   http://<host>:8090/
   ```

   手机同理（服务端按 UA 返回移动版）。

2. 页面加载后立即展示标注入口，并后台请求 `/api/annotations` 取已有标注与原因表
   （失败不影响入口显示，只影响回显）。
   需要临时关掉入口时加 `?annotate=0`；旧链接 `?annotate=1` 仍然可用。

3. 标注方式：

| 位置 | 操作 |
|---|---|
| 列表卡片 | `✓` 值得收录；`✕` 弹出原因，点一下就保存 |
| 详情面板 | `✓ 值得收录` / `✕ 不该收录`（**读完正文再判断，推荐这里**）、`撤销` |
| 待复核条目 | 按钮语义变为「该收（规则漏收）」/「确实不该收」，其余一致 |
| 重复点击 | **再次点击同一判定不会改变状态**（幂等，2026-11-14 起）；撤销请点详情面板的「撤销」或按 `U` |
| 快捷键（桌面） | `J/K` 上下条、`1` 值得收录、`2` 不该收录（再选原因）、`U` 撤销、`Esc` 关闭原因弹层 |

4. 标注完成后卡片会置灰显示"已标：原因"，详情面板同步显示"今日已标 N 条"。
   这只是提醒，不设"必须标完"的进度目标。

## 3 原因标签（每个都必须能对应到可调项）

| 代码 | 标签 | 对应打分/配置里的旋钮 |
|---|---|---|
| `commercial` | 商业/厂商宣传 | `quality.commercial_penalty_max`、发布稿封顶、商业负向词 |
| `off_topic` | 与安全无关 | 负向过滤、强词权重 |
| `ai_hollow` | AI 空泛 | `ambiguity_rules.standalone_score`、① 类主题权重 |
| `shallow` | 太浅/无新增 | `quality.depth_bonus_max`、深度门槛 |
| `duplicate` | 重复/转载 | `dedup.similarity_threshold`、正文指纹 |
| `stale` | 过时/旧闻 | `dedup.max_days`、`report.rolling.window_days` |
| `source_noise` | 信源噪音 | `quality.source_tiers`、单源配额 |
| `cve_noise` | 漏洞详情，不关注 | ③ 类主题权重、内容类型系数 |

`reject` 必须带原因；前端提供「不说明原因」兜底（保存为 `unspecified`）。
不建议多选原因：多选会让"这条为什么被否"归因模糊，反而不利于调规则。

## 4 数据格式

- 位置：`data/state/annotations/annotations-YYYY-MM.jsonl`
- 一行一条事件，**只追加不改写**；撤销也写成新记录（`verdict=clear`）
- 复盘时按 `(annotator, item_id)` 取最后一条，`clear` 视为未标注

| 字段 | 说明 |
|---|---|
| `v` | 结构版本（当前 1） |
| `id` | 事件编号 |
| `ts` | 本机时区 ISO 时间 |
| `annotator` | 登录用户名；未启用认证时为 `local` |
| `item_id` | 报告条目的稳定主键（URL 哈希） |
| `verdict` | `accept` / `reject` / `clear` |
| `reason` | 原因代码；`reject` 无原因时为 `unspecified` |
| `baseline` | 标注时规则的判定：`accepted` / `review`（用于区分"误收"与"漏收"） |
| `snapshot` | 标题、链接、信源、分类、日期、当时分数、评分拆解、命中词、摘要 |

单条约 1–2KB；一天 85 条全标约 150KB。

## 5 接口

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/annotations` | 当前生效标注列表 + 原因表 + 当天计数 + 标注人 |
| POST | `/api/annotations` | 新增标注（`accept` / `reject` / `clear`） |
| GET | `/api/annotations/export?month=YYYY-MM` | 导出 JSONL（缺省导出全部月份） |

全部走后台现有的 Basic Auth；写接口还要求同源 + `X-Requested-With` 头，
与收藏接口一致，阻断跨站伪造请求。

> **标注人恒为 `local`**（单用户部署，2026-11-14 确认）：线上认证由 Caddy + hub-auth 前置完成，
> `cybersec-favorites.service` 显式清空了 Basic Auth，代码因此回退到 `local`。多人协作前
> 需要由反代透传用户名，否则归属不可用——目前按单用户设计，不做这件事。

> 反代场景：若 POST 返回 403「拒绝跨站请求」，是 `Origin` 带端口而 `Host` 未带端口。
> 与收藏接口同样的处理——Caddy 需 `header_up Host {hostport}`。

## 6 导出与备份

```powershell
# 本机直接导出（不经 HTTP）
python -m pipeline.annotations --out annotations.jsonl

# 从线上拉回本机做分析（标注存在你读报告的那台机器上）
curl -u "$env:CONFIG_USERNAME:$env:CONFIG_PASSWORD" `
     "http://<host>:8090/api/annotations/export?month=2026-11" -o annotations_2026-11.jsonl
```

- 目录不参与保留期清理，也不需要备份策略：随时可全量导出。
- 删除某条误标：在页面上再点一次撤销即可；不要手工改 JSONL（会破坏事件链）。
- 换设备标注时，同一 `item_id` 以最后一次写入为准（`annotator` 相同的前提下）。

## 7 后续（二期）

`scripts/annotation_report.py`（规划中）读取导出的 JSONL，输出：

- **误收率** = 已上屏里被标"不该收"的比例
- **漏收率** = 待复核里被标"该收"的比例
- **一致率趋势** = 标注与规则判定一致的比例（按周）
- 按原因 / 信源 / 命中词 / 分类四张聚合表
- 规则调整建议表（样本 <8 条或占比 <70% 不下结论）

建议只输出"改哪个配置项、依据几条样本"，实际改动一律人工确认，
并仍然走 `python scripts/scoring_golden_test.py` 与真实数据回归。

## 8 已知局限

- **只覆盖看得到的内容**：被分数直接丢弃（<50）的条目没有入口，因此"漏收"只能从
  待复核里发现一部分。二期可加"候选池抽样"补齐。
- **标注是主观的**：同一人前后也可能摇摆，因此保留事件链、看趋势而不是单条结论。
- **不自动改配置**：这是有意为之——评分词表是踩过很多坑才调稳的，自动生效会让
  一次手滑污染整周版面。
